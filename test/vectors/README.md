# Relay format 2 test vectors

`relay_format_2_vectors.txt` was generated by `gen_relay_vectors.c`, compiled against the **real firmware code** at WestshoreWatch-Firmware tag `x1m1-1.4-westshore` (commit e151a72):
- the 1.4 relay: `WSW-Firmware/main/odid_decoder.c` + `odid_encoder.c`;
- the 1.3 relay: `tests/odid_location/legacy_1_3`, which is cddc1df verbatim;
- the drone side: opendroneid-core-c.

It was run once on a GitHub Linux runner (temporary branch, since deleted). sha256 `70fd87ef0976d40209a7a899c3435b9786e9abfb33530281baeb600bcbadd9f1`, 310 cases.

One case per line, semicolon-separated, with `-` meaning unknown:
```
name;legacyPack77hex;rf2Pack102hex;droneLoc25hex;specHeading;specSpeed;status;height;lat;lon
```
- `legacyPack`: what a 1.3 relay broadcasts.
- `rf2Pack`: what a 1.4 relay broadcasts.
- The spec columns: the opendroneid reference decode of the drone's own Location.

Used by `test/relayFormat.test.mjs` (TS) and `android/app/src/test/.../OdidParserTest.kt` (Kotlin). Swift has no test target; it mirrors the Kotlin code.
